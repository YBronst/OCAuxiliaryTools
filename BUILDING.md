# Building OCAuxiliaryTools on macOS from Source

This guide covers building the project locally on macOS with Qt 5.15.2 (matching the project's CI), including a known linker issue on modern Xcode versions and how to clean up afterwards.

## Prerequisites

### 1. Xcode Command Line Tools

```bash
xcode-select --install
```

### 2. Qt 5.15.2 via `aqtinstall`

The project's CI is pinned to Qt 5.15.2, so this guide installs that exact version. No Qt account or GUI installer required.

```bash
pip3 install aqtinstall
aqt install-qt mac desktop 5.15.2 clang_64 -O ~/Qt5
```

Add it to your `PATH` for the current terminal session:

```bash
export PATH="$HOME/Qt5/5.15.2/clang_64/bin:$PATH"
```

> To make this permanent, add the `export` line to your `~/.zshrc` (or `~/.bash_profile`). Leaving it session-only is safer if you also install other Qt versions later and want to switch between them explicitly.

Verify it resolved correctly:

```bash
qmake -v
which qmake
```

This should report `Using Qt version 5.15.2` from a path under `~/Qt5/...`. If it doesn't, something else earlier in your `PATH` (e.g. a Homebrew Qt install) is taking priority.

## Known issue: `ld: framework 'AGL' not found`

Qt 5.15's build configuration still links against `AGL.framework`, an old Apple OpenGL/Carbon framework that has been **removed from recent macOS SDKs** (Xcode 15+). This causes every Qt 5.15 project to fail at the link step on a modern toolchain — it's not specific to this project.

**Fix: patch the reference out of your local Qt installation** (not the project source):

```bash
QTDIR=$HOME/Qt5/5.15.2/clang_64
grep -rln "framework AGL" "$QTDIR"
```

This should print one or more file paths (typically under `mkspecs/` and/or a `.prl` file near `lib/`). Strip the token from each:

```bash
grep -rln "framework AGL" "$QTDIR" | while read -r f; do
  sed -i.bak 's/-framework AGL//g' "$f"
done
```

This only needs to be done once per Qt installation — it patches your local Qt copy, not the repository.

## Building

From the project root:

```bash
cd /path/to/OCAuxiliaryTools
qmake
make 2>&1 | tee build.log
```

If something fails, check the end of the log:

```bash
tail -60 build.log
```

On success, the built app is at:

```bash
open bin/release/OCAuxiliaryTools.app
```

(or `bin/debug/` if built in debug mode.)

## Cleaning up build artifacts

Since the project is a git repo, the safest way to remove everything generated by `qmake`/`make` is via `git clean`, which only touches untracked/ignored files.

**Preview what would be removed** (dry run — deletes nothing):

```bash
git clean -ndx
```

You should see things like `Makefile`, `bin/`, `*.o`, `moc_*`, `ui_*`, `qrc_*`, `build.log`, `.qmake.stash`, and any `.bak` files from the AGL patch step above.

**Actually remove them:**

```bash
git clean -fdx
```

| Flag | Meaning |
|------|---------|
| `-n` | Dry run — show what would be deleted |
| `-f` | Force the deletion |
| `-d` | Include untracked directories (e.g. `bin/`) |
| `-x` | Also remove files ignored via `.gitignore` (build output usually is) |

## Uninstalling Qt entirely

`aqtinstall` just extracts Qt into a folder — there's no separate uninstaller. Removing it is just deleting that folder:

```bash
rm -rf ~/Qt5
```

Then, if you added the `export PATH=...` line to your shell config permanently, remove it from `~/.zshrc` (or `~/.bash_profile`).

Optionally remove the `aqtinstall` tool itself if you don't plan to use it again:

```bash
pip3 uninstall aqtinstall
```

No other system-level files are created — everything lives in user-space folders.
